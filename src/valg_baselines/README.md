# Valg artifact subset reproduction

This module records Gengkun Shao's small-scale reproduction of the official
Valg artifact.  It is separate from the offline budget-selection experiment in
`src/run_experiments.py`.

## What is executed

For each configured Java project, `run_subset.sh` invokes the official artifact
scripts inside the prepared `valg-repro` Docker container:

1. no-RV Maven test baseline;
2. ValgJ selective monitoring;
3. JavaMOP full monitoring;
4. ValgT selective trace collection;
5. TraceMOP full trace collection.

The runner does not change the Valg algorithm.  A failed trace mode is recorded
and does not erase earlier successful Java-mode results.

## Reproduce

Start Docker Desktop and use the already prepared container from the artifact
setup.  From the repository root:

```bash
bash src/valg_baselines/run_subset.sh check
bash src/valg_baselines/run_subset.sh xeger
bash src/valg_baselines/run_subset.sh javadbf
bash src/valg_baselines/run_subset.sh route53-infima
bash src/valg_baselines/run_subset.sh jlemmagen
```

New runs are written to `results/valg_baselines/runs/<timestamp>/`.  Each run
contains complete console logs, official artifact output, mode exit codes, and
a compact `summary.csv` generated by `summarize_subset.py`.

To rebuild the committed summary tables and figure from the four compact raw
CSVs:

```bash
python -m pip install -r src/valg_baselines/requirements.txt
python src/valg_baselines/plot_results.py
```

## Interpretation limits

The committed data are one run per project and configuration.  They provide
end-to-end wall-clock time and artifact-emitted trace/violation counts, but no
confidence intervals.  Only `jlemmagen` has a complete ValgT/TraceMOP pair.
The results therefore constitute a partial artifact reproduction, not a
reproduction of the paper's complete 64-project evaluation.
